# موقع خمسة ديجيتال 🛍️

موقع متجر متكامل — واجهة عصرية + قائمة بريدية بترحيب تلقائي + لوحة مالك لإرسال الإيصالات والملفات.
كل الخدمات المستخدمة **مجانية 100%**.

## المكونات
| الملف | وظيفته |
|---|---|
| `index.html` | الصفحة الرئيسية (المنتجات + التسجيل بالإيميل) |
| `admin.html` | لوحة المالك — تفتحها من `موقعك/admin` |
| `api/subscribe.js` | يحفظ الإيميل في قاعدة البيانات ويرسل الترحيب |
| `api/subscribers.js` | يعرض المسجلين (للمالك فقط) |
| `api/send-email.js` | يرسل إيميلاً (إيصال/ملف/إعلان) لواحد أو للجميع |
| `api/admin-login.js` | دخول المالك بكلمة السر |
| `supabase-setup.sql` | كود إنشاء جدول المسجلين — يُشغَّل مرة واحدة |

## خطوات التشغيل (30 دقيقة تقريباً)

### 1) حساب GitHub ورفع الملفات
1. سجّل في github.com بإيميل المتجر الجديد.
2. أنشئ مستودعاً جديداً (New repository) باسم `khamsa-site` — عام (Public).
3. اضغط «uploading an existing file» واسحب **كل محتويات هذا المجلد** دفعة واحدة → Commit.

### 2) قاعدة البيانات — Supabase (مجاني)
1. سجّل في supabase.com بنفس حساب GitHub → New project (اختر أي منطقة قريبة، واحفظ كلمة سر القاعدة).
2. من القائمة: SQL Editor → New query → الصق محتوى `supabase-setup.sql` → Run.
3. من Settings → API انسخ: **Project URL** و **service_role key** (السري — لا تشاركه أبداً).

### 3) الإيميلات — Gmail (مجاني: ~500 إيميل/يوم، بدون تحقق جوال إضافي)
1. من إيميل المتجر (Gmail): افتح myaccount.google.com → **Security**.
2. فعّل **2-Step Verification** (التحقق بخطوتين) إن لم يكن مفعلاً.
3. في نفس صفحة الأمان ابحث عن **App passwords** (كلمات مرور التطبيقات) → أنشئ واحدة باسم `khamsa-site` → انسخ الكود المكون من 16 حرفاً — هذا هو `GMAIL_APP_PASSWORD` (لا تشاركه مع أحد).

> بديل اختياري: إذا نجح تسجيلك في Brevo لاحقاً، أضف متغيري `BREVO_API_KEY` و`SENDER_EMAIL` وسيستخدمه الموقع تلقائياً بدل Gmail (حد أعلى: 300/يوم لكن أفضل للتوسع مستقبلاً).

### 4) النشر — Vercel (مجاني)
1. سجّل في vercel.com بحساب GitHub → Add New → Project → اختر `khamsa-site` → Deploy.
2. بعد النشر: Settings → Environment Variables وأضف:

| الاسم | القيمة |
|---|---|
| `SUPABASE_URL` | رابط مشروع Supabase |
| `SUPABASE_SERVICE_KEY` | مفتاح service_role |
| `GMAIL_USER` | إيميل المتجر (Gmail) |
| `GMAIL_APP_PASSWORD` | كلمة مرور التطبيق (16 حرفاً من الخطوة 3) |
| `SENDER_NAME` | خمسة ديجيتال |
| `ADMIN_PASSWORD` | كلمة سر قوية للوحة المالك — اخترها بنفسك |
| `TAMARA_API_TOKEN` | (اختياري) مفتاح تمارا السري — لتفعيل التقسيط |
| `TAMARA_NOTIFICATION_KEY` | (اختياري) مفتاح إشعارات تمارا — لتوقيع الويبهوك |
| `TAMARA_MODE` | (اختياري) `sandbox` للتجربة — احذفه للوضع الحقيقي |

3. Deployments → أعد النشر (Redeploy) حتى تُفعَّل المتغيرات.
4. رابط موقعك: `khamsa-site.vercel.app` (تقدر تغيره من Settings → Domains).

### 5) جرّب
- افتح الموقع → سجّل إيميلك → المفروض توصلك رسالة الترحيب.
- افتح `موقعك/admin` → ادخل بكلمة السر → تشوف الإيميل المسجل، وجرب إرسال رسالة.

### 6) اربط كل شيء
- حط رابط الموقع في **وصلاتي** وفي **بايو تيك توك**.
- لتعديل المنتجات والأسعار: عدّل قائمة `PRODUCTS` أعلى `index.html` (ورقم الواتساب في `WHATSAPP`).

## 💜 تفعيل تمارا (التقسيط) — اختياري

1. من [لوحة تمارا](https://partners.tamara.co) → **General settings → API Tokens**
   اضغط على أيقونة النسخ بجانب **API Token** (القيمة مخفية بالنجوم — النسخ يأخذها كاملة).
2. في Vercel → Settings → Environment Variables أضف:
   - `TAMARA_API_TOKEN` = المفتاح المنسوخ
   - `TAMARA_NOTIFICATION_KEY` = قيمة **Notification key** من نفس الصفحة
   - `TAMARA_MODE` = `sandbox` إذا كنت تجرّب بمفاتيح التجربة (احذفه للحقيقي)
3. من **General settings → Webhooks** أضف رابطاً جديداً:
   `https://<موقعك>/api/tamara-webhook`
4. أعد النشر (Redeploy)، ثم افتح `موقعك/admin` وشغّل فحص الإعدادات.

**كيف يشتغل:** الموقع يسأل تمارا عن حدود التقسيط ويعرض الزر فقط للمنتجات
داخل هذه الحدود (عادةً من 100 ر.س فأكثر)، فلا يرى العميل زراً يفشل عند الضغط.
بعد الدفع يعتمد الموقع الطلب ويحصّله من تمارا تلقائياً ثم يرسل الملفات.
والويبهوك شبكة أمان: لو أغلق العميل المتصفح قبل رجوعه، الملفات تُرسل رغم ذلك.

> **الشعار:** `pay/tamara.svg` شعار مبسّط. لو تبغى الرسمي، حمّله من
> لوحة تمارا → **Partner Marketing Kit** واستبدل الملف بنفس الاسم.

## 🔗 حسابات التواصل

تُدار كلها من `موقعك/admin` → لوحة **«🔗 حسابات التواصل»**:
تيك توك، إنستغرام، سناب شات، إكس، يوتيوب، فيسبوك، تيليجرام + رقم الواتساب.
تظهر كأيقونات أسفل كل صفحة، وأي خانة تتركها فاضية ما تظهر أيقونتها.
رقم الواتساب المحفوظ يُستخدم في **كل** أزرار الواتساب بالموقع تلقائياً.

> يتطلب تشغيل `supabase-setup.sql` مرة أخرى لإنشاء جدول `settings`.

## 🔍 تحسين محركات البحث (SEO)

| الملف | وظيفته |
|---|---|
| `robots.txt` | يسمح بفهرسة المتجر ويمنع `/admin` و`/checkout` و`/thanks` و`/api` |
| `sitemap.xml` | خريطة كل الصفحات القابلة للفهرسة — يقرأها قوقل |
| `p/<key>.html` | صفحة مستقلة لكل منتج (20 صفحة) بمحتوى فريد وسعر وبيانات منظمة |
| `tools/build_seo.py` | يولّد الاثنين الأخيرين من بيانات المنتجات نفسها |

### مهم: بعد أي تعديل على المنتجات أو الأسعار

```bash
python tools/build_seo.py
```

يقرأ `PRODUCTS` من `index.html` وملفات كل منتج من `api/_delivery.js`،
ثم يعيد بناء صفحات `p/` و`sitemap.xml`. **لا تعدّل ملفات `p/` يدوياً** — تُكتب فوقها.

السبب أن السعر يظهر في ثلاثة أماكن (الصفحة، البيانات المنظمة، نتائج قوقل)،
وسعر في نتائج البحث يخالف سعر الصفحة يُعدّ تضليلاً ويعرّض الإعلانات للإيقاف.

### ⭐ نظام التقييمات

نجوم التقييم في نتائج قوقل مغرية، وتلفيقها يعرّض الموقع لعقوبة «إجراء يدوي»
تشيل النتائج المنسّقة من كل الموقع. لذلك النظام مبني بحيث **لا يمكن** تلفيق تقييم:

1. بعد كل عملية شراء يُرسَل رابط تقييم **موقّع** مع إيميل التسليم
2. الرابط يحمل توقيع HMAC مشتقاً من مفتاح سري — لا يُخمَّن ولا يُزوَّر
3. الخادم يرفض أي تقييم لا يقابله **طلب حقيقي** في جدول `orders`
4. تقييم واحد لكل طلب (قيد فريد في القاعدة، لا فحص برمجي فقط)
5. لا يظهر أي تقييم قبل **اعتمادك** له من لوحة الأدمن
6. `aggregateRating` لا يُحقن في الصفحة **إلا إذا وُجد تقييم معتمد واحد على الأقل**

> شارة **«شراء موثّق»** تظهر للطلبات المدفوعة فقط. طلبات كود الخصم 100%
> تظهر بشارة «طلب مجاني» — تمييز صادق يفيد القارئ.

التسليم اليدوي من لوحة المالك **لا يرسل** دعوة تقييم عمداً، حتى لا يوجد
طريق يستطيع المالك عبره توليد دعوات بلا شراء.

**متغيّر اختياري:** `REVIEW_SECRET` لتوقيع الروابط. إن لم تضبطه يُستخدم
`SUPABASE_SERVICE_KEY`. لو غيّرته تبطل الروابط القديمة غير المستخدمة.

**يتطلب** تشغيل `supabase-setup.sql` مرة أخرى لإنشاء جدول `reviews`.

### 🎁 الهدية المجانية (صفحة /free)

صفحة هبوط تستهدف بحث «تعليم الحروف للأطفال pdf» وتحوّل الباحث لمشترك ثم مشترٍ:
- الهدية ملف حقيقي: أول 4 صفحات من كراسة الحروف، يولّدها `python tools/make_free_sample.py`
- **لازم ترفعها مرة واحدة:** `python tools/upload_files.py` (صارت ضمن قائمة الملفات المتوقعة)
- عند التسجيل (من /free أو من قسم الهدية بالرئيسية): يظهر رابط التحميل فوراً
  **ويصل نفسه في إيميل الترحيب** مع دعوة لشراء الكراسة الكاملة
- بدون رفع الملف: التسجيل يشتغل عادي والإيميل يرجع للصيغة القديمة (رد «هديتي»)

### 📣 شريط الإعلان + تحسينات المتجر

- **شريط إعلان** أعلى كل الصفحات: نصه وإظهاره من الأدمن → لوحة حسابات التواصل
- **زر واتساب عائم** في الرئيسية وصفحات المنتجات — رقمه من إعدادات الأدمن
- **صفحة 404** مخصصة تعيد الزائر للمتجر أو الهدية
- **أزرار مشاركة** (واتساب + نسخ الرابط) في كل صفحة منتج
- **أسئلة شائعة** في الرئيسية + قسم «ليش نحن» بست بطاقات (رابط النافبار #why)

### ربط الموقع بـ Google Search Console (مرة واحدة)

1. [search.google.com/search-console](https://search.google.com/search-console) → **إضافة موقع** → اختر **بادئة عنوان URL** والصق `https://khamsa-site.vercel.app`
2. اختر طريقة **«علامة HTML»** وانسخ قيمة `content`
3. افتح `index.html` وابحث عن `google-site-verification` — أزل علامتَي التعليق `<!--` و`-->` وألصق القيمة
4. ارفع الملف وأعد النشر ثم اضغط **تحقّق**
5. من القائمة → **ملفات Sitemap** → أضف `sitemap.xml`

### 📈 تفعيل تتبع Google Ads (مرة واحدة)

الموقع جاهز لتسجيل **كل عملية شراء بقيمتها الفعلية بالريال** في حساب إعلاناتك —
تحتاج فقط معرّفين تحصل عليهما من قوقل وتلصقهما في لوحة الأدمن:

1. أنشئ حساباً في [ads.google.com](https://ads.google.com)
2. **الأهداف (Goals) → التحويلات (Conversions) → إنشاء إجراء تحويل جديد**
   → **موقع إلكتروني** → أدخل رابط موقعك
3. اختر فئة **«شراء» (Purchase)** → طريقة الإعداد: **«التثبيت اليدوي» (Install the tag yourself)**
4. بعد الإنشاء افتح تفاصيل التحويل وخذ من كود الحدث قيمة `send_to`:
   `AW-123456789/AbCdEfGhIj` — الجزء الأول هو **المعرّف** والجزء بعد الشرطة
   المائلة هو **تسمية التحويل**
5. افتح `موقعك/admin` → لوحة **«📈 قوقل أدز والتحليلات»** → الصق الاثنين → حفظ
6. (اختياري) أضف معرّف GA4 من [analytics.google.com](https://analytics.google.com)
   لتشوف سلوك الزوار كاملاً

**وش يتسجل تلقائياً بعد الحفظ:**
- `conversion` (شراء) في صفحة الشكر — بالقيمة الفعلية بعد الخصم + رقم العملية
  (لا يتكرر التحويل لو حدّث العميل الصفحة، لأن قوقل يتجاهل نفس transaction_id)
- `begin_checkout` في صفحة الطلب — يغذي حملات إعادة الاستهداف
- بدون معرّفات محفوظة: **صفر سكربتات تتبع** — الموقع نظيف تماماً

### 🏷️ شارات المنتجات

تُدار من لوحة الأدمن → **«🏷️ شارات المنتجات»**:
- **الوضع الأوتوماتيكي:** «الأكثر مبيعاً 🔥» و«الأكثر طلباً» تُحسبان من طلباتك
  الحقيقية في قاعدة البيانات (بشرط 3 طلبات فأكثر — لا شارة على طلب يتيم)
- **يدوي لأي منتج:** اكتب أي نص (جديد 🌟، عرض رمضان..) وله الأولوية على الأوتوماتيكي
- **إخفاء:** اكتب `-` في خانة المنتج
- الخانة الفاضية = الأوتوماتيكي إن وُجد، وإلا الشارة الافتراضية المطبوعة في الكود

### قبل تشغيل إعلانات قوقل

- ✅ صفحة الشروط والاسترجاع والخصوصية موجودة في `/policies` (يشترطها قوقل)
- ✅ بيانات تواصل واضحة (بريد + واتساب + حسابات تواصل)
- ✅ أسعار ظاهرة وصريحة بالريال
- ⬜ **وجّه الإعلان لصفحة المنتج** `‎/p/<key>` لا للصفحة الرئيسية — صفحة تطابق كلمة البحث ترفع نقاط الجودة وتخفّض سعر النقرة
- ⬜ صفحة الدفع محجوبة عن الفهرسة عمداً — لا تستخدمها كصفحة هبوط للإعلان

## ⚠️ حد الـ12 دالة في Vercel (خطة Hobby)

خطة Hobby المجانية تسمح بـ **12 دالة كحد أقصى لكل نشر**، وكل ملف في `api/`
لا يبدأ بشرطة سفلية يُحسب دالة. تجاوز الحد = فشل النشر بالكامل.

لذلك جُمِّعت النقاط خلف موزّعَين، والمجموع الآن **8 دوال** (باقي 4 للتوسّع):

| الملف | يخدم |
|---|---|
| `api/admin.js` | `?op=` login / subscribers / deliver / send-email / check-files / health / discounts |
| `api/tamara.js` | `?op=` config / start / webhook |
| `api/settings.js` | حسابات التواصل (GET عام + POST للمالك) |
| `api/subscribe.js` · `check-discount.js` · `free-order.js` · `pay-start.js` · `verify-pay.js` | نقاط عامة |

**قاعدة عند الإضافة مستقبلاً:** لا تُنشئ ملفاً جديداً في `api/` مباشرة —
اجعله وحدة باسم `_op-<الاسم>.js` وأضفه لقائمة `OPS` في الموزّع المناسب.
الملفات التي تبدأ بـ `_` لا تُحسب دوال.

الروابط القديمة (`/api/admin-login`، `/api/tamara-webhook` …) ما زالت تعمل
عبر `rewrites` في `vercel.json` — فرابط الويبهوك المسجَّل في لوحة تمارا يبقى صالحاً.
